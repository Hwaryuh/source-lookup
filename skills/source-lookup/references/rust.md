# Rust

## Pin the version

`cargo metadata --format-version 1` lists every package in the resolved graph with `name`,
`version`, `source` and `manifest_path`. Add `--locked` to fail instead of updating the lock file.

The same crate often appears in several versions in one graph. To see which crate pulls which
version, run `cargo tree -i <crate>@<version>`. Use the version that the crate you are editing
depends on.

`locate.ps1 -Lang rust -Package <crate>` runs `cargo metadata` and prints every match.

## Source

The source folder is the folder that contains `manifest_path`:

- registry crates: `$CARGO_HOME/registry/src/<index>-<hash>/<crate>-<version>/`. `CARGO_HOME`
  defaults to `~/.cargo`.
- git dependencies: `$CARGO_HOME/git/checkouts/<repo>-<hash>/<rev>/`.
- path dependencies: inside the workspace.

Standard library: `rustup component add rust-src`. The source is then in
`$(rustc --print sysroot)/lib/rustlib/src/rust/library/`.

## Signatures

Search for `pub fn <name>`, `pub struct <Name>`, `pub trait <Name>` and `impl ... for <Type>`.
Many items are re-exported with `pub use`. Follow the re-export to the crate that defines the item.

## Traps

- **Feature flags.** Items behind `#[cfg(feature = "...")]` exist only when the feature is enabled.
  Check the enabled features in the `resolve.nodes[].features` field of `cargo metadata`, not only in
  `Cargo.toml`.
- **Macros.** Items generated by `macro_rules!` or derive macros cannot be found by text search.
  Use `cargo expand` if it is installed.
- **Breaking changes between minor versions before 1.0.** For example 0.21 and 0.22 of the same
  crate are separate APIs.
- **Language changes.** For recently stabilized features, fetch `rust-releases`. For edition changes,
  fetch `rust-edition-guide` (see `refs.json`). Neither one documents crate APIs.

## Check

`cargo check --all-targets`. Run `cargo clippy` when the project uses it. Compiler errors name the
external type and the version that `cargo metadata` resolved.
